# -# 📱 Прогнозирование типа смартфона методом k ближайших соседей (KNN)

Учебный проект по машинному обучению: программа предсказывает, какой смартфон
предпочитает пользователь — **iPhone** или **Android** — на основе анкеты из
20 вопросов о привычках, бюджете, сфере деятельности и отношения к технологиям.

Модель — **KNeighborsClassifier** из scikit-learn. Проект демонстрирует полный
пайплайн: загрузка CSV → очистка данных → кодирование признаков → подбор
гиперпараметров → оценка качества → интерактивные режимы демонстрации и
тестирования.

## ✨ Возможности

- 📊 Загрузка и очистка данных из CSV-файла с ответами респондентов.
- 🧹 Автоматическая обработка «грязных» числовых значений (`100.000`, `2,5`, пробелы).
- 🔤 One-Hot-кодирование категориальных признаков.
- 🧩 Разбиение мультивыборных ответов (`Экосистема;Надежность`) на бинарные признаки.
- 🎯 Подбор гиперпараметров KNN (`k`, вес, метрика) через `GridSearchCV`.
- 🔁 Кросс-валидация `StratifiedKFold` для честной оценки на малой выборке.
- 📈 Матрица ошибок и график важности признаков (`permutation_importance`).
- 🖥️ **Интерактивное меню**:
  - режим **демонстрации** — ввод профиля нового пользователя вручную;
  - режим **тестирования** — прогон по заранее заданным профилям с известным ответом;
  - сохранение отчёта в CSV.
- 💾 Графики и отчёты автоматически сохраняются в папку `results/`.

## 🧠 Как это работает

### 1. Предобработка

- **Числовые признаки** (`7, 8, 9, 13, 18`) очищаются от пробелов и
  разделителей тысяч: `"100.000" → 100000`, `"2,5" → 2.5`.
- **Пропуски** заполняются медианой (числовые) или модой (категориальные).
- **Стандартизация** `StandardScaler` для числовых признаков — KNN
  чувствителен к масштабу.
- **One-Hot-кодирование** категориальных признаков через `OneHotEncoder`.
- **Мультивыбор** `"Экосистема;Надежность"` разбивается через
  `MultiLabelBinarizer` на отдельные бинарные столбцы.

### 2. Разбиение данных

```python
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)
```

- 75 % (30 записей) — обучение
- 25 % (11 записей) — тест

### 3. Подбор гиперпараметров

`GridSearchCV` перебирает:

- `k` — только **нечётные** значения `[3, 5, 7, 9, 11]` (чтобы избежать
  ничьих при голосовании);
- `weights` — `uniform` или `distance`;
- `metric` — `euclidean` или `manhattan`;
- кросс-валидация — `StratifiedKFold(n_splits=5)`.

### 4. Оценка качества

- `accuracy`, `precision`, `recall`, `f1-score` по каждому классу;
- **матрица ошибок** (`confusion_matrix`);
- **кросс-валидация** по 5 фолдам — более честная оценка при малой выборке.

### 5. Важность признаков

`permutation_importance` перемешивает каждый исходный признак и смотрит,
насколько падает accuracy. Результат сохраняется в виде графика.

## ⚠️ Ограничения

- **Очень маленькая выборка** — всего 41 запись. Метрики нестабильны,
  accuracy может «гулять» от 60 % до 100 % при разных разбиениях.
- **Дисбаланс классов** — Android 22 / iPhone 19.
- **Шуточный признак** `21. Как часто кушаете яблоки?` удалён в коде —
  он не несёт смысловой нагрузки.
- **Выбросы** (например, бюджет `1 000 000 ₽`, которого нет в датасете)
  сильно искажают расстояния в KNN и могут приводить к неожиданным прогнозам.
- **`StandardScaler` чувствителен к выбросам.** Если вводить значения вне
  диапазона обучающей выборки, прогноз может стать почти случайным.
- **Одно разбиение train/test** даёт шумную оценку — ориентируйтесь в первую
  очередь на кросс-валидацию.
